# Antigravity Truth Guard: 5 Універсальних Загальних Законів

[English version (global-rules.md)](global-rules.md) | **Українська**

## Закон 1: Обґрунтований контекст (global-no-guessing)
Будь-якому ШІ-агенту чи розробнику суворо заборонено вгадувати, екстраполювати або вигадувати архітектуру кодової бази, схеми баз даних, контракти API чи бізнес-правила. Перед початком планування або написання коду агент ЗОБОВ'ЯЗАНИЙ викликати `truth_search` для отримання підтверджених фактів. Якщо специфікація відсутня в базі, агент повинен уточнити у користувача або явно позначити поле як невідоме/null замість вигадування довільних схем.

## Закон 2: Міжсегментна ізоляція (global-surgical-scope)
Суворе дотримання меж Чистої Архітектури (Clean Architecture). Один коміт або крок агента НІКОЛИ не повинен змішувати зміни у кількох архітектурних шарах одночасно (Domain Core, Application / Use Cases, Infrastructure / Persistence, Delivery / HTTP Adapters, Presentation / UI). Якщо функція потребує змін у кількох шарах, агент зобов'язаний розбити задачу на окремі послідовні кроки, де кожен шар компілюється з 0 помилок (`Zero-Diagnostic Rule`) і проходить усі тести.

## Закон 3: Чесність верифікації (global-verification-honesty)
Перевірка плану ніколи не повинна фальсифікуватися, підроблятися або обходитися. Кожен план, поданий на `truth_verify_plan`, повинен явно посилатися на реальні `cited_fact_ids`, отримані через `truth_search`. Пропуск компілятора (`tsc --noEmit`), вимкнення тестів чи використання неперевірених чеків суворо заборонені. Якщо отримано `approved: false` — агент зобов'язаний негайно зупинитися і виправити план.

## Закон 4: Облік за методом проводок (global-defensive-code)
Усі фінансові та грошові суми зберігаються виключно як цілі числа копійок (`integer cents`). Дробові типи даних (Float/Double) для грошей суворо заборонені. Фізичні залишки та резерви на складі ніколи не перезаписуються прямими абсолютними числами; будь-яка зміна здійснюється виключно через незмінну проводку дельти (+ або -) з обов'язковим зазначенням первинного документа.

## Закон 5: Ієрархія правди (global-project-priority)
У будь-якій ситуації, коли правило конкретного проекту (`project_id != 'global'`) суперечить загальному глобальному правилу, проектне правило має абсолютний пріоритет (`priority: HIGH (PROJECT OVERRIDE)`). Глобальні правила є базовими орієнтирами (`priority: BASE (GLOBAL)`), тоді як локальні доменні правила проекту визначають специфіку застосунку.
